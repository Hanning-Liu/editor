# Qwen 建模工具升级计划 · 2026-11-09

目标：正常建模工具由 Qwen 自主选择，保留当前项目边界；以真实执行、场景回读和截图验收，区分接入与已验证。

1. 盘点全部 MCP 工具，按读取、建筑、房间、屋顶、家具、材质、结构、脚本、视觉、导出分类。
2. 新增工具目录与按需加载，保留完整参数；旧项目默认获得新增正常建模工具，仍尊重用户关闭的已有插件。
3. 配置独立本地 MCP 执行进程、Three.js/Blender 编译、原生离屏截图、资产预览及本地 Qwen 图片 sampling。
4. 完善错误恢复、图片返回、导出交付、批量子调用校验、跨轮次撤销重做和执行记录。
5. 在新建测试场景实际运行本地 Qwen，核对建模节点、材质、楼梯、屋顶、视觉图片、图片分析、撤销及导出；检查已有用户场景未改变。

验收：正常工具在目录可发现、可加载完整 schema；模型实际自主调用新增工具成功；场景变更有回读证据；截图实际传回模型；生成文件可下载；失败不伪报成功。记录未验证的高级参数和依赖限制，不把接口枚举作为功能验证。

## 真实 Qwen 网页任务

1. 创建6×5米客厅，墙高2.8米，精确涂色 #88bbdd，检查场景。
2. 查重后创建35°双坡屋顶，挑檐0.3米；获取768×480真实截图，模型据图说明，再检查。
3. 创建指定位置的独立直跑楼梯，检查并导出JSON；实际点击网页下载按钮并解析文件确认包含楼梯及屋顶。
4. 生成并调用简短Three.js模块，创建直径0.3米、高0.6米的圆柱展示台；回读位置[2,0,2]、真实包围盒[0.3,0.6,0.3]、编译GLB可被浏览器获取。

其他配套验收：两个图片分析工具实际调用本地Qwen；Three.js与Blender编译均写入测试项目；屋顶迁移同时验证内存夹具及真实持久化场景；聊天跨轮次撤销重做完整图比对；用户停止不修改场景；GLB下载296700字节、63个mesh、有效glTF 2.0容器。

## 实际限制

- 复杂“凳子+楼梯”组合曾遇到原有4分钟单次生成超时，失败记录保留；拆分后的楼梯/导出与短代码自定义任务成功。当前等待上限10分钟，可配置，不保证任意复杂任务一次成功。
- 原生82项的成功调用只覆盖记录中的参数与场景，不能等同于所有高级参数组合验证。Qwen端是上述四组代表任务；没有让模型逐一自主执行全部82项。
- 房间照片尺寸估计有明显偏差，不能当作测量。GLB采用外部纹理引用；截图光照覆盖、参考图裁剪、piece文字生成服务、payloadFile读取器仍有明确限制。
